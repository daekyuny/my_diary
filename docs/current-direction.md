# 현재 합의와 작업 상태

## 확정한 방향

- 개인 Gmail 계정으로 Google Sheets API를 사용한다.
- 기존 Google Drive `My Diary` 폴더 안에 `My Diary` 스프레드시트 파일 하나를 둔다.
- 기본 탭은 `일기`, `추가항목`, `일정`, `설정`이다. 연도별 파일 분리는 우선 하지 않는다.
- 모든 기기가 같은 파일 ID의 데이터를 API로 직접 읽고 수정한다. PC 폴더 동기화에 의존하지 않는다.
- 날짜를 기본 필드로 둔다. 사용자 정의 항목은 웹앱에서 추가·수정·삭제한다. 기분·버전은 필수 사용자 항목이 아니다.
- 목록·카드·캘린더는 교체 가능한 보기이다. 카드를 중심 구조로 강제하지 않는다.
- Google Calendar API로 작성 날짜의 일정을 표시한다.
- 기존 Drive 파일은 사용자가 직접 삭제한다. 에이전트는 삭제·자동 정리를 실행하지 않는다.
- 프로젝트 루트 `keep-data.zip`은 향후 기존 데이터 import용 원본이다. 삭제·변경하지 않는다. Git 및 배포에서 제외한다. 이번 확인 시 약 89MB이며 Git에서 제외되어 있다.

## 구현 상태

- 루트 화면을 반응형 Sheets 일기 앱으로 교체했다. 목록·카드·캘린더, 날짜별 작성, 검색, 사진, 사용자 정의 항목 설정을 제공한다.
- 추가 항목은 고유 ID를 사용하며 이름 변경·숨김 후에도 기존 값을 유지한다. 정의는 시트에 함께 저장한다.
- Sheets 저장 계층은 일기당 현재 행을 직접 갱신한다. 연결 시 과거 이력은 최신 값만 남긴다. 동시 저장은 마지막 요청을 반영한다. 사진은 같은 Drive 폴더의 attachments에 저장한다.
- 연결 전 기록과 계정별·시트별 임시 저장소를 분리한다. 연결 전 기록의 계정 이동은 설정에서 명시적으로 실행한다.
- Keep ZIP 가져오기와 ZIP 내보내기를 구현했다. 프로젝트 원본 ZIP은 열거나 변경하지 않았다.
- 중단한 Firestore 실험과 의존성은 제거했다. 기존 Drive 화면은 legacy.html에 보존했다.
- Keep 읽기 실험은 src/keep-probe.html에 남아 있다. 개인 Gmail 로그인에서 keep.readonly invalid_scope로 실패했으며 실제 Keep 데이터 조회는 하지 못했다.
- 자동 테스트는 모의 Google API와 독립 브라우저를 사용한다. 실제 Gmail OAuth, API 활성화, 실제 Drive 폴더 접근은 사용자 브라우저에서 확인해야 한다.
- 앱은 Firebase Hosting에 배포되어 있다. Sheets API 주소 오류를 발견해 공식 sheets.googleapis.com 주소로 수정했다. 기존 빈 파일 복구·계정 임시 기록 업로드·재연결을 회귀 테스트로 검증한다. 실제 계정의 최종 저장 확인은 사용자 로그인 후 진행한다. 설치·테스트·운영 제한은 README.md를 참고한다.
