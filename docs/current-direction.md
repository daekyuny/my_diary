# 현재 합의와 작업 상태

## 확정한 방향

- 개인 Gmail 계정으로 Google Sheets API를 사용한다.
- 기존 Google Drive `My Diary` 폴더 안에 `My Diary` 스프레드시트 파일 하나를 둔다.
- 기본 탭은 `일기`, `휴지통`, `일정`, `설정`이다. 연도별 파일 분리는 우선 하지 않는다.
- 모든 기기가 같은 파일 ID의 데이터를 API로 직접 읽고 수정한다. PC 폴더 동기화에 의존하지 않는다.
- 날짜를 기본 필드로 둔다. 사용자 정의 추가항목 기능은 제거한다. 기분·버전은 필수 사용자 항목이 아니다.
- 목록·카드·캘린더는 교체 가능한 보기이다. 카드를 중심 구조로 강제하지 않는다.
- Google Calendar API로 작성 날짜의 일정을 표시한다.
- 이전 저장 방식의 Drive 파일은 사용자가 직접 삭제한다. 현재 앱에서 첨부 삭제·휴지통 완전 삭제를 저장할 때의 파일 정리는 사용자가 요청한 범위에서 앱이 수행한다.
- 프로젝트 루트 `keep-data.zip`은 향후 기존 데이터 import용 원본이다. 삭제·변경하지 않는다. Git 및 배포에서 제외한다. 이번 확인 시 약 89MB이며 Git에서 제외되어 있다.

## 구현 상태

- 루트 화면을 반응형 Sheets 일기 앱으로 교체했다. 목록·카드·캘린더, 날짜별 작성, 검색, 사진을 제공한다.
- 추가항목의 필요한 사진·일정 메타데이터는 일기 행 O열로 이관한다. 설정의 이관 완료 확인 후 사용자가 해당 워크시트를 삭제한다.
- Sheets 저장 계층은 일기당 현재 행을 직접 갱신한다. 연결 시 과거 이력은 최신 값만 남긴다. 같은 일기의 양쪽 수정은 덮어쓰지 않고 충돌로 보존한다. 사진은 같은 Drive 폴더의 attachments에 저장한다.
- 연결 전 기록과 계정별·시트별 임시 저장소를 분리한다. 연결 전 기록의 계정 이동은 설정에서 명시적으로 실행한다.
- Keep ZIP 가져오기와 ZIP 내보내기를 구현했다. 프로젝트 원본 ZIP은 변경하지 않았다. 진단 중 기록 수와 첨부 크기만 확인했으며 외부로 전송하지 않았다.
- 중단한 Firestore 실험과 의존성은 제거했다. 기존 Drive 화면은 legacy.html에 보존했다.
- 개인 Gmail에서 사용할 수 없었던 Keep API 읽기 실험과 전용 테스트는 제거했다. Keep ZIP 가져오기는 계속 지원한다.
- 자동 테스트는 모의 Google API와 독립 브라우저를 사용한다. 실제 Gmail OAuth, API 활성화, 실제 Drive 폴더 접근은 사용자 브라우저에서 확인해야 한다.
- 앱은 Firebase Hosting에 배포되어 있다. Sheets API 주소 오류를 발견해 공식 sheets.googleapis.com 주소로 수정했다. 기존 빈 파일 복구·계정 임시 기록 업로드·재연결을 회귀 테스트로 검증한다. 사용자가 PC·모바일 동기화와 시트의 네 기록을 확인했다. 설치·테스트·운영 제한은 README.md를 참고한다.

- 2026-09-11: 수동 저장·닫기 확인, 휴지통과 기간별 완전 삭제, 빈 기본 시트 정리로 전환했다.
- OAuth 코드 교환 및 토큰 자동 갱신 서버를 추가했다. Secret Manager의 DIARY_GOOGLE_CLIENT_SECRET 버전 2를 함수에 배포했고 DIARY_AUTH_ENABLED를 활성화했다. 클라이언트 비밀번호 불일치를 수정했다.

- 2026-09-11: 빈 행 실제 정리·휴지통 워크시트 분리, 편집 중 자동 동기화 보류, 새 항목 입력란 즉시 추가, 연결 버튼 비활성화, UUID 원본/썸네일 분리와 첨부 삭제 후 파일 정리를 적용했다. 임시 숨김 잠금 탭으로 여러 기기의 행 이동·저장을 순차 실행한다.

- 기존 일기는 읽기 모드에서 제목 옆 수정 버튼으로 편집한다. 저장은 로컬 완료 후 목록으로 복귀하고 Sheets 전송은 백그라운드로 처리한다. 전송 확인과 원격 병합은 최신 기기 편집을 덮어쓰지 않도록 트랜잭션에서 확인한다. 사진 파일명은 숨기고 첨부 삭제 버튼은 수정 모드에만 표시한다.

- 최근 100개 본문은 일기 날짜 기준 기기에 보관하며 변경 식별자가 다른 본문만 갱신한다. 과거 본문은 조회 시 읽는다. 미전송 수정은 캐시 정리에서 보호하고 같은 일기의 양쪽 수정은 비교 후 별도 사본으로 보존한다.

## 세션 종료 메모 · 2026-09-11

- Sheets 쓰기는 최대 20개씩 묶고 읽기·쓰기 요청을 각각 61초당 45회로 제한한다. 429 응답은 자동 재시도한다. 사용자가 실제 ZIP 가져오기 저장 완료를 확인했다.
- 추가항목 제거·최근 100개 캐시·양방향 변경 동기화는 커밋 `a98c0e8`로 배포했고 PC·모바일 Chromium 및 Safari 엔진 자동 검사가 통과했다.
- 기존 시트는 새 버전 앱 연결 시 사진·일정 정보를 일기/휴지통 O열로 이관한다. 사용자는 모든 기기를 업데이트하고 설정의 **이관 완료**를 확인한 뒤 추가항목 워크시트를 직접 삭제한다. 사용자 시트의 이관 완료 여부는 아직 확인하지 않았다.
- 대대적인 스키마 변경은 향후 Excel 다운로드 → 로컬 일괄 변환·검증 → 새 Sheets 파일 업로드 → 앱 연결 전환 방식도 고려한다. 사진 원본과 Drive 파일 ID는 보존해야 한다. 아직 별도 도구는 구현하지 않았다.
- `keep-data.zip`과 `imports/`의 변환 백업·날짜 보정 자료는 Git/배포에서 제외한 채 보존했다. 빌드·브라우저 테스트 생성물과 이번 세션의 임시 진단 파일은 정리했다.

## 세션 메모 · 2026-09-29

- 사용자가 모든 기기를 Drive 앱 전용 저장소(appdata)로 옮겨 사용 중임을 확인했다. 시트 → appdata 이전 코드(`sheets.js`, `sheet-lock.js`, `sheets-quota.js`, 설정의 이전 UI)와 관련 테스트를 제거했다. 이전 때 만든 `seed` 파일은 계속 읽는다.
- `app.js`를 역할별 모듈로 나누고 `AGENTS.md`를 현행화했다. 순수 함수는 `tests/journal-modules.test.mjs`로 검증한다.
- 첫 세대 Drive 폴더 앱(`legacy.html`, `src/app.js`, 날씨·알림 모듈)과 Cloudflare 푸시 Worker, 관련 테스트를 제거했다. OAuth 범위에서 `drive.file`을 빼고 `drive.appdata`와 선택적 `calendar.readonly`만 요청한다.
- 성능: 시작 시 편집기 잠금 해제, 묶음당 목록 1회·체크섬 검증, Drive changes API 증분 확인과 목록·토큰의 IndexedDB 보관을 적용했다. 모의 Drive 기준 저장 6→2, 새로고침 7→2, 25초 주기 확인 1요청. 수정본 압축(4번)도 적용해 각 일기의 최신 수정본만 남긴다. 다른 기기가 삭제된 파일을 읽으면 건너뛴다.

## 세션 메모 · 2026-09-30

- 이슈 #1~#4: 모바일 상단을 압축했다(한 줄 문구 숨김, 클라우드 배너 한 줄, 여백 축소). 빠른 작성 카드는 오늘 일기가 없을 때만 보이는 "오늘 기록 남기기" 한 줄로 바꿨고, 캘린더에서 날짜를 고르면 그 날짜용으로 계속 보인다(`quickEntryVisible`).
- 목록 카드의 삭제 버튼을 없애고 읽기 모드 하단의 삭제하기·복원하기가 즉시 실행된다. 휴지통 이동 후 5초 동안 되돌리기 토스트를 띄우며, 그동안 클라우드 저장 완료 같은 일반 안내는 토스트를 덮지 않는다. 수정 모드의 삭제하기는 기존처럼 저장으로 확정한다.
- `window.confirm`(저장하지 않고 닫기, 휴지통 완전 삭제)은 `#small-dialog`를 재사용하는 `confirmDialog`로 바꿨다. 브라우저 테스트는 브라우저 확인창이 뜨면 실패한다.

## 세션 메모 · 2026-10-01

- 남은 이슈 #5~#11을 이슈별 커밋으로 처리했다. 날짜 표기 통일(`dateLabel`), 읽기 화면 이전·다음·스와이프·글자 크기·글자 수 숨김, 캘린더 한국어 월·배지·날짜 스크롤, 검색 강조(`search.js`), 다크 모드, 사진 최적화(`media.js`), 동영상 첨부.
- localStorage 설정에 `textSize`, `theme`, `photoQuality` 필드를 추가했다(기존 필드는 그대로). `index.html` 머리의 인라인 스크립트가 첫 그리기 전에 테마와 글자 크기를 적용한다.
