# Lessons

## 2026-09-30 · 문서·기록만 바꾼 커밋도 CI와 배포를 돌렸다

- 상황: `tasks/todo.md` 하나를 커밋해 푸시했는데 워크플로가 전체 테스트(약 5분)와 Firebase 배포까지 실행했다.
- 규칙: 앱 동작과 무관한 커밋(`tasks/`, `docs/`, `*.md`, `.claude/`)은 제목에 `[skip ci]`를 붙인다. 이 저장소는 전에도 그렇게 했다.
- 더 나은 해결: 워크플로 `push` 트리거에 `paths-ignore`를 두어 사람이 기억하지 않아도 되게 한다. 사용자에게 제안한 상태.

## 2026-10-01 · 여러 커밋을 한 번에 push할 때 맨 위 커밋의 [skip ci]가 배포를 막는다

- 상황: 기능 커밋 8개 위에 문서 커밋을 `[skip ci]`로 올렸다. GitHub은 push의 맨 위 커밋 메시지에 `[skip ci]`가 있으면 그 push 전체의 워크플로를 건너뛰므로 기능 커밋이 배포되지 않을 뻔했다.
- 규칙: 워크플로에 `paths-ignore`(`**.md`, `docs/**`, `tasks/**`, `.claude/**`)가 생겼으므로 문서 커밋에 `[skip ci]`를 붙이지 않는다.

## 2026-10-01 · `grep`으로 끝나는 `&&` 체인이 실패한 e2e를 통과로 넘겼다

- 상황: `npm run test:e2e | grep ... && git commit && git push`로 묶었더니 grep이 "1 failed" 줄을 찾아 성공으로 끝나 실패한 채 push됐다.
- 규칙: 테스트 결과는 종료 코드로 판단한다. 출력은 파일로 남기고 `echo "exit $?"`를 확인한 뒤 커밋·push를 별도 단계로 실행한다.

## 2026-10-01 · 시간 초과는 트레이스로 멈춘 단계를 확인한 뒤 고친다

- 상황: 업데이트 테스트의 30초 초과를 "서비스 워커 설치가 느려서"로 짐작해 제한을 60초로 늘렸지만 다시 실패했다. 트레이스를 보니 본문은 2초에 끝났고, 정리 단계의 `page.goto('about:blank')`가 끝나지 않았다.
- 규칙: 시간 초과는 `test-results/*/trace.zip`에서 마지막으로 시작된 동작을 먼저 확인한다. 제한 시간 늘리기는 원인을 확인한 뒤에만 한다.
